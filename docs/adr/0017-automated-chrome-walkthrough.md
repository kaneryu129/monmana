# ADR-0017: デスクトップ Chrome の通し確認を自動化する

- **ステータス**: Accepted
- **日付**: 2026-08-19
- **関連**: ADR-0007, ADR-0016
- **関連 Issue**: #46, #87, #89

## コンテキスト

ADR-0007 で、動作確認は Chrome (macOS) と iPhone の 2 環境で行うと決めた。
その手順を `docs/mvp-checklist.md` に書き出したが、そこには次の前提が置かれていた。

> ヘッドレス Chrome では IndexedDB も Service Worker も応答しないため（#17 で判明）、
> 音・オフライン動作・ストレージの保持は実機でしか確かめられない

#46 の通し確認に着手して測ったところ、**この前提が事実と異なっていた。**

- `--headless=new` と実プロファイル（`--user-data-dir`）を渡せば IndexedDB は動く。
  記録は Chrome を終了して開き直しても残る
- Service Worker も登録され、オフラインにして再読み込みしても起動する
- `<audio>` の再生も動く。`currentTime` が進むかどうかで、鳴ったかを機械的に判定できる
- `Page.setWebLifecycleState` でページを凍結でき、背面に回った状態を再現できる

なお `#17` は「学習セッション記録と成長状態更新のユースケースを実装する」であり、
ヘッドレスでの制約について何も述べていない。引用そのものが誤っていた。

実際に確かめたところ、仕様書 14 章の完成条件のうち **49 項目を自動で通せた。**
残りの 10 項目は iOS 固有か、日をまたぐ必要があるものだった。

さらに、自動化の過程で**手作業では見つけにくい不具合が 2 件見つかった。**

- **#87**: 「音を試す」が `<audio>` から鳴っていなかった。
  デスクトップでは Web Audio に落ちて鳴るため、耳では気づけない。
  iOS の消音スイッチを入れたときだけ無音になる
- **#89**: 背面から戻ったあとの完了で終了音が鳴らない。
  `play()` が拒否も成功もせず止まるため、**例外としても現れない**。
  再生位置が進んでいるかを見て初めて分かる

どちらも「押して、聴く」確認では検出できない種類だった。

## 決定

**デスクトップ Chrome の通し確認は、`tools/walkthrough` の自動確認で行う。**

- 実行は手元から `npm run walkthrough`。本番ビルドを `npm run preview` で配信して当てる
- **依存を足さない。** Node の組み込み WebSocket で CDP を直接叩く
- **アプリのコードには手を入れない。** 25 分の早送りは、ページ側の `Date.now` を
  差し替えて行う（`src/domain/timer.ts` が経過を現在時刻の差分で求めているため、これで足りる）
- 判定できない項目は「実機のみ」として結果に残し、`docs/mvp-checklist.md` に送る

**iPhone の確認は自動化しない。** ADR-0007 のとおり、WebKit の検証点は実機だけである。

## 検討した選択肢

### 案 A: 手作業のまま続ける

- 利点: 道具を持たなくてよい。実際の見え方・聞こえ方で判断できる
- 欠点: 毎回 25 分待つ。回帰は人の記憶に頼る。#87 と #89 はこの方法では見つからなかった
- 却下理由: 自動化できないという前提が誤りだった。**測れるものを人手に残す理由がない**

### 案 B: Playwright か Puppeteer を入れる

- 利点: 記述が短くなる。待機やセレクタの扱いが整っている
- 欠点: ブラウザを二重に持つことになり、依存が重い。
  今回必要な操作（凍結、オフライン、ファイル投入、`<audio>` の観測）はいずれも CDP の生の呼び出しで足りる
- 却下理由: 得るものに対して重い。**確認の道具が本体より重いのは倒錯している**
- 備考: 検査項目がさらに増えて手に負えなくなったら、この判断は見直してよい

### 案 C: GitHub Actions で回す

- 利点: 毎回自動で走る。忘れない
- 欠点: 凍結や音の再生を CI で安定させられる見込みが薄い。無料枠を消費する（最優先の制約）
- 却下理由: **不安定な検査は、通っても落ちても信用されなくなる。** 手元で回す

### 案 D: vitest で賄う

- 利点: すでにある。速い
- 欠点: IndexedDB・Service Worker・`<audio>`・ページの凍結が再現しない。
  #89 は本物のブラウザでしか現れない
- 却下理由: 単体テストの範囲を超えている。両方を持つ

## 結果と影響

### 良い影響

- 仕様書 14 章の完成条件を、同じ手順で何度でも確かめられる
- iPhone に持ち込む前に、Chrome で潰せるものを潰せる
- 実機で見るべき項目が 10 件に絞られ、確認が現実的な長さになる
- 音が「鳴った」ことを、耳ではなく再生位置で判定できる

### 受け入れるトレードオフ

- ハーネスは画面のクラス名に依存する。UI を変えれば壊れる。**壊れたら直す**
- 早送りは `Date.now` の差し替えで行うため、実時間で 25 分動かした確認にはならない
  （一時停止・再開・凍結からの復帰は実時間で確かめている）

### 残るリスクと緩和策

- **「Chrome で通った」は「iPhone で通る」の保証ではない。** この原則は変わらない。
  #87 と #89 はどちらも Chrome で見つけたが、影響が出るのは主に iOS だった
- 音の善し悪し、モンステラの見え方、文言の受け取り方は判定できない。
  ここは人が見るものとして `docs/mvp-checklist.md` に残す

## 備考

`docs/mvp-checklist.md` から、誤っていた前提の記述を取り除いた。
ヘッドレスでは確認できないと再び判断する場合は、**何がどう動かなかったのかを添えて**
この ADR を見直すこと。前回はそれが無かったために、誤った前提が長く残った。
