# ADR-0005: ホスティングは GitHub Pages とする

- **ステータス**: Accepted
- **日付**: 2026-08-15
- **関連**: ADR-0001, ADR-0004

## コンテキスト

ADR-0001 で Web (PWA) を、ADR-0004 で Vite による静的ビルドを採用した。
成果物は静的ファイル一式であり、これを配信する場所を決める必要がある。

制約は「完全無料」。ここで言う無料とは、**無料枠の消費を気にする必要がない**ことを含む。
無料枠に上限があり、超過すると課金される、あるいはサービスが停止するものは、
「完全無料」の要件を厳密には満たさない。

なお `monmana` リポジトリは **public** である。これが判断に効く。

## 決定

**GitHub Pages でホスティングし、GitHub Actions でビルド・デプロイする。**

- `main` ブランチへのマージをトリガーに自動デプロイする
- 公開 URL は `https://kaneryu129.github.io/monmana/`
- Vite の `base` を `/monmana/` に設定する

## 検討した選択肢

### 案 A: GitHub Pages — 採用

- 利点:
  - **public リポジトリでは完全無料**。帯域・ビルドともに実質的な上限を気にする必要がない
  - GitHub Actions も **public リポジトリでは実行時間無制限**
  - すでにコードが GitHub にあり、追加のアカウント登録が不要
  - HTTPS が自動で有効。**PWA と Service Worker には HTTPS が必須**であるため、これは要件
- 欠点:
  - サブパス配信になるため Vite の `base` 設定が必要
  - SPA のルーティングで直接アクセス時に 404 になる（対処法は確立している）
- 採用理由: 「無料枠を気にしなくてよい」という条件を唯一明確に満たす

### 案 B: Vercel / Netlify / Cloudflare Pages

- 利点: デプロイ体験が洗練されている。プレビューデプロイが便利
- 欠点:
  - 無料枠に上限がある（帯域、ビルド回数、ビルド時間）。
    個人利用で超える可能性は低いが、**上限が存在する時点で「完全無料」の保証にならない**
  - 商用利用の制限や、無料枠の条件変更リスクがある
  - 追加のアカウント登録と、GitHub との連携設定が必要
- 却下理由: 制約の解釈上、上限のない選択肢が存在するならそちらを採る

### 案 C: ホスティングしない（ローカルでのみ実行）

- 利点: 何も要らない
- 欠点: スマートフォンで使えない。**ホーム画面への追加ができず、
  ADR-0001 / ADR-0002 で緩和策としたストレージ永続化が機能しない**
- 却下理由: モンまなは日々の学習で使うアプリであり、スマートフォンで動かないと意味がない

## 結果と影響

### 良い影響

- 費用・無料枠の懸念が完全に消える
- リポジトリと配信が同じ場所にまとまり、管理対象が増えない
- HTTPS により PWA / Service Worker の要件を満たす

### 受け入れるトレードオフ

**リポジトリを public に保つ必要がある。**
private リポジトリで GitHub Pages を使うには GitHub Pro（有料）が必要になるため、
public であることがこの決定の前提条件になる。

現時点でリポジトリは public であり、学習記録は端末内にのみ保存される（ADR-0002）ため、
ソースコードの公開によって個人データが露出することはない。

### 残るリスクと緩和策

**リスク 1: SPA のルーティングで 404 になる**

GitHub Pages は静的ファイル配信のため、`/monmana/timer` への直接アクセスで 404 を返す。

緩和策:
- `404.html` を `index.html` と同一内容にしてフォールバックさせる、
  または HashRouter を使う。実装時に選択して Issue で記録する

**リスク 2: サブパス配信によるアセットパスの破綻**

`https://kaneryu129.github.io/monmana/` はルート直下ではないため、
絶対パスでアセットを参照すると壊れる。

緩和策:
- Vite の `base: '/monmana/'` を設定し、アセット参照は Vite の解決に任せる
- Service Worker のスコープも同様にサブパスを意識する

## 備考

将来、独自ドメインを使いたくなった場合、GitHub Pages は無料で独自ドメインに対応できる
（ドメイン取得費用は別途かかるため、「完全無料」制約下では現状スコープ外）。
その場合サブパスの問題は解消するため、本 ADR の緩和策は不要になる。
