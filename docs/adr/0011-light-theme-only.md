# ADR-0011: アプリはライトテーマ固定とする

- **ステータス**: Accepted
- **日付**: 2026-08-15
- **関連**: ADR-0008
- **関連 Issue**: #7

## コンテキスト

デザイントークンを定義するにあたり（#7）、ダークテーマを持つかどうかを決める必要が生じた。

iOS には端末全体のダークモードがあり、対応していないアプリは
「作りが古い」と受け取られることがある。一方で仕様書 13 章は配色を明確に指定している。

> 白や淡いベージュをベースにする
> 深い緑を主なアクセントにする
> 斑入りの段階では、白と淡い黄緑を上品に使う

## 決定

**ライトテーマのみを実装する。ダークテーマは持たない。**

`prefers-color-scheme: dark` に対する上書きを書かない。
端末がダークモードでも、モンまなは紙の色のまま表示する。

## 検討した選択肢

### 案 A: ライトテーマ固定 — 採用

- 利点:
  - **仕様書 13 章の配色をそのまま実装できる**
  - モンステラの緑と白斑が、設計された前提（淡いベージュの地）の上で成立する
  - 実装量が半分で済み、配色の破綻を検証する箇所が減る
- 欠点: 端末のダークモードと調和しない。夜間の使用で眩しく感じる可能性がある
- 採用理由: 後述のとおり、ダークテーマは配色の入れ替えでは済まず、
  モンステラの再設計を伴うため

### 案 B: ダークテーマも用意する

- 利点: 端末の設定に追従できる。夜間に目が疲れにくい
- 欠点:
  - **モンステラの配色を作り直す必要がある。**
    ADR-0008 で決めた手描き風は、淡いベージュの地に深い緑を置く前提で描かれている。
    暗い地に置くと、奥の葉（`--c-leaf-far` #1E4A31）が背景に沈む
  - **白斑（`--c-variegation` #FFFFFF）が暗い地では強く出すぎる。**
    仕様書 13 章は斑を「上品に」使うと定めており、
    暗い地の上の純白はその指定と噛み合わない
  - 検証が 2 倍になる。ADR-0007 で確認環境を 2 つに絞った方針とも合わない
- 却下理由: 単なる色の入れ替えでは済まず、**MVP のクライマックスである
  Lv.10 の白斑の見え方を作り直すことになる。** MVP の範囲を超える

## 結果と影響

### 良い影響

- 仕様書 13 章の世界観をそのまま実装できる
- モンステラの配色を 1 通りだけ管理すればよい
- 画面ごとの配色検証が半分で済む

### 受け入れるトレードオフ

**端末がダークモードでも明るい画面が出る。**

夜間に使うと眩しく感じる可能性がある。
ただしモンまなは 25 分の学習中に眺めるアプリであり、
学習時には手元も明るいことが多いと考えられる。

`<meta name="theme-color" content="#FBF9F3">` を指定済みで、
ホーム画面から起動した際のブラウザ UI も紙色に揃う。

## 備考

夜間の眩しさが実際に問題になった場合は、
本 ADR を `Superseded` としてダークテーマ導入の ADR を起票すること。
その際は**モンステラの暗い地向けの配色を設計し直すことが必要になる**点を、
作業量の見積もりに含めること。色の入れ替えだけでは終わらない。

なお、`design/` 以下の検討用ページ（画風スタディ、モックアップ）は
閲覧者のテーマに追従してよい。あれは製品ではなく資料であり、
モンステラを載せる面だけ紙色で固定してある。
