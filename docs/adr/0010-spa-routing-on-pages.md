# ADR-0010: SPA の直リンク対策は 404.html フォールバックとする

- **ステータス**: Accepted
- **日付**: 2026-08-15
- **関連**: ADR-0005, ADR-0001
- **関連 Issue**: #6, #17

## コンテキスト

ADR-0005 でホスティングを GitHub Pages に決めた際、
「SPA のルーティングで直接アクセス時に 404 になる」をリスクとして挙げ、
**対処法の選択は実装時に決めて記録する**としていた。本 ADR がその決定にあたる。

GitHub Pages は静的ファイル配信のため、`/monmana/timer` のような
アプリ内ルートへ直接アクセスすると、該当するファイルが存在せず 404 を返す。
仕様書 4 章の画面遷移を React Router で実装する以上、必ず踏む問題である。

## 決定

**`dist/index.html` を `dist/404.html` にコピーし、GitHub Pages のフォールバックとして使う。**
HashRouter は使わない。

デプロイのワークフローで、ビルド後にコピーする。

```yaml
- name: 404.html を用意する
  run: cp dist/index.html dist/404.html
```

存在しないパスへのアクセスに対し、GitHub Pages は `404.html` を返す。
その中身が `index.html` と同一であるため SPA が起動し、
React Router が URL を見てルートを解決する。

## 検討した選択肢

### 案 A: 404.html フォールバック — 採用

- 利点:
  - **URL が素直**。`/monmana/timer` のまま扱える
  - 実装がビルド後の 1 行コピーだけで済む
  - ルータの選択に制約を持ち込まない
- 欠点:
  - HTTP のステータスコードとしては 404 が返る（内容は正しく表示される）
- 採用理由: URL の素直さを保ったまま、最小の変更で解決できる

### 案 B: HashRouter を使う

- 利点: サーバ側の対処が一切不要。どこに置いても確実に動く
- 欠点:
  - URL が `/monmana/#/timer` になる
  - **ホーム画面に追加した PWA での挙動が扱いにくい。**
    ADR-0001 / ADR-0002 でホーム画面追加をデータ保全の要としているため、
    この領域に不確実性を持ち込みたくない
  - 将来 URL を共有する機能を足すとき、ハッシュ付き URL は扱いが面倒になる
- 却下理由: 対処が 1 行で済む案 A がある以上、URL の形を犠牲にする理由がない

### 案 C: 静的に各ルートの HTML を生成する

- 利点: 正しいステータスコードが返る
- 欠点: ルートを増やすたびにビルド設定を変える必要がある。SSG の仕組みを持ち込むことになる
- 却下理由: ADR-0004 で「使わない機能のために複雑さを持ち込まない」方針を採っている。過剰

## 結果と影響

### 良い影響

- URL が素直なまま保たれる
- ルータの実装（#17）が GitHub Pages を意識しなくてよくなる

### 受け入れるトレードオフ

**存在しないパスでも HTTP 404 が返る。**

本アプリは検索エンジンに載せる必要がなく（ログイン前提の個人利用、ADR-0002）、
表示は正しく行われるため、実用上の問題は生じない。

なお、この方式では**アプリ側で「そのルートは無い」と判断する必要がある。**
未定義のパスに対しては、React Router 側でホームへ寄せる、
あるいは静かな案内を出す（仕様書 13 章のトーンを守り、ユーザーを責めない）。
実装は #17 で行う。

## 備考

`base: '/monmana/'` の設定（ADR-0005）と組み合わせて初めて成立する。
Vite の `base` を変えるときは、この 404.html の扱いも合わせて確認すること。
